**Owner:** Young Kim · **Co-author:** Zichuo Wang · **Reviewers:** all

## What goes here

- Mock-up screens (images, or an exported file from whatever tool you use).
- The preliminary user manual.

## The constraint that matters

Both must be **consistent with the TO-BE scenarios in `../02-as-is-to-be/`** — in particular the
Top Priority scenario. A mock-up showing a flow no TO-BE scenario describes, or a manual
documenting a capability with no requirement behind it, is the failure mode here. Coordinate
with D-1 (James + Austin) from W2, when the scenarios are chosen, and bring the mock-up to each
Sunday checkpoint so the team can check it against the scenarios as it develops.

## Accessibility is the subject matter, not a nicety

THEIA's users are blind and visually impaired. A mock-up that only works as a visual layout is
describing the wrong product. Say how each screen is reached and conveyed non-visually, and
write the user manual as something a screen reader would speak.
